# Maestro

النسخة الإنجليزية: [README.md](README.md)

**وكيل Antigravity يخطط ويبني، بينما يتولى Claude Code الإشراف والمراجعة.**

يحوّل Maestro أداة [Claude Code](https://claude.com/claude-code) إلى قائد مشرف على تطبيق وكيل Antigravity. تتناقش وتعصف ذهنياً حول الميزة مع Claude، ثم يرسل Claude وصف المهمة إلى Antigravity. يضع Antigravity خطة التنفيذ ويبني الميزة بالبدء بالاختبارات أولاً، ثم يتحقق Claude باستقلالية تامة من الكود والاختبارات قبل أن يطلب منك الموافقة على الدمج. لا يكلّف انتظار Antigravity أي استهلاك توكن.

```
 أنت ──عصف ذهني──▶ Claude Code (Maestro) ──task-NNN.md──▶ وكيل Antigravity
                          ▲      │                                │
                          │      └─ خمول (دون استهلاك توكن)      │ ينفّذ
                          │                                       │ (قد يسأل عبر MCP)
                          └──── يتحقق: الاختبارات، الفروقات ◀── task-NNN.done.md (تقرير)
                                 │
                                 └─ فشل؟ ──▶ مهمة إصلاح ──▶ Antigravity ...
```

## الحالة

**الإصدار 0.6.0 (تجريبي).** يعتمد Maestro على آليات داخلية غير موثقة في Antigravity (انظر [الهيكلية: القيود](docs/en/architecture.md#limitations) (بالإنجليزية)).

| المنصة | الحالة |
|---|---|
| Windows 10/11 | مختبرة مع Antigravity 2.29، بما في ذلك قناة الأسئلة عبر MCP من البداية إلى النهاية |
| macOS | مطبّقة، **غير مختبرة** |
| Linux (X11) | مطبّقة، **غير مختبرة** |
| Linux (Wayland) | مطبّقة، **غير مختبرة**. تُكتب نصوص المهام كمسودات، وتضغط على مفتاح Enter بنفسك. |

### البيئة المختبرة

| المكوّن | البيئة المختبرة |
|---|---|
| نظام التشغيل | Windows 11 |
| تطبيق الوكيل | تطبيق وكيل Antigravity 2.29 |
| نموذج المنفّذ | Gemini 3.8 Flash بمستوى High |
| المراجع | Claude Code |

لم تُختبر النماذج أو مستويات التفكير الأخرى، ولا أنظمة التشغيل الأخرى.

## المتطلبات

- [Claude Code](https://claude.com/claude-code) (واجهة سطر الأوامر أو تطبيق سطح المكتب)
- **تطبيق وكيل Antigravity** مع تسجيل الدخول (ملاحظة: Antigravity IDE (محرّر الكود) تطبيق منفصل ولا يُستخدم هنا)
- بيئة Python 3.10 أو أحدث (المكتبة القياسية فقط)، وتكون متوفرة كأمر `python` على Windows و`python3` على macOS وLinux
- نظام macOS: إذن إمكانية الوصول (Accessibility) للطرفية أو التطبيق الذي يشغّل Claude Code (مطلوب لإرسال مفتاح الإدخال Return إلى Antigravity)
- أنظمة Linux: حزمة `xdg-utils` (وأداة `xdotool` على واجهة X11 للضغط على مفتاح Enter تلقائياً)

## التثبيت

**نظام Windows**

```powershell
git clone https://github.com/SalehOsman/Maestro C:\Tools\Maestro
python C:\Tools\Maestro\install.py
```

**نظاما macOS و Linux**

```bash
git clone https://github.com/SalehOsman/Maestro ~/tools/maestro
python3 ~/tools/maestro/install.py
```

يتحقق برنامج التثبيت من المتطلبات الأساسية ويثبّت مهارة Claude Code في المسار `~/.claude/skills/maestro`.

**اختياري: تفعيل نقاط مراجعة الخطة والأسئلة أثناء تنفيذ المهمة عبر MCP.**
شغّل برنامج التثبيت مع المعامل `--with-mcp`:

```bash
python install.py --with-mcp
```

يسجّل هذا الأمر خادم Maestro MCP في إعدادات Antigravity. أعد تشغيل تطبيق وكيل Antigravity بالكامل بعد ذلك. يُوصى بهذا الإجراء بشدة حتى يتمكن Claude من مراجعة الخطط قبل كتابة الكود.

لإزالة المهارة وتسجيل MCP:

```bash
python install.py --uninstall
```

## البدء السريع

1. **افتح مجلد المشروع** في تطبيق وكيل Antigravity وأرسل أي رسالة واحدة لتسجيل المجلد لدى Antigravity.
2. **افتح المجلد نفسه في Claude Code** واطلب إضافة ميزة:
   ```
   /maestro Add a CSV export to the reports page
   ```
3. **وافق على وصف المهمة واترك Antigravity مفتوحاً.** ينسّق Claude المهمة، ويراجع خطة المنفّذ واختباراته، ثم يعرض العمل المكتمل لتوافق على دمجه.

للاطلاع على دليل إرشادي كامل، ومرجع ملفات الحالة، واستكشاف الأخطاء وإصلاحها، راجع [دليل البدء السريع](docs/ar/quickstart.md).

## الأدوار والمنهجيات

لكل طرف مهام محددة وثابتة. راجع وثيقة [الأدوار والمسؤوليات](methodologies/ROLES.md) (بالإنجليزية) لمعرفة العقد الكامل بين الأطراف.

| الدور | الطرف | المسؤوليات |
|---|---|---|
| **صاحب القرار** | **أنت** | تحديد ما يُبنى والأولويات، والموافقة على كل عملية دمج |
| **المنفّذ** | **Antigravity** | إعداد الخطة، والتنفيذ بالبدء بالاختبارات أولاً، والتحقق الذاتي بالأدلة الملموسة، وتقرير الإنجاز |
| **المراجع** | **Claude Code** | إعداد أوصاف المهام، وفحص الخطة عند نقاط المراجعة، والتحقق المستقل (الاختبارات، والفروقات، والاختبارات المحجوبة، واختبار الطفرات)، وقرارات المراجعة |

توجد **نقطتا توقف** لكل ميزة: نقطة مراجعة الخطة والتقرير النهائي. تُصنف نتائج المراجعة كبنود معرّفة بحالات `blocking` أو `should-fix` أو `note`، وذلك خلال **جولتي مراجعة كحد أقصى**.

| المنهجية | الفئة المستهدفة | الأدوات الخارجية |
|---|---|---|
| `standard` (موصى بها) | أي مشروع | لا شيء؛ تستخدم مشغّل الاختبارات وأدوات التدقيق الخاصة بالمشروع نفسه. |
| `uem` | مستخدمو منهجية الهندسة الموحدة | Superpowers و EGM و Harness Engineering و AgentShield و ECC (اختياري) |
| `custom` | المشاريع ذات سير العمل المخصص | لا شيء؛ تطبّق عقد Maestro الأدنى، مع بقاء المراجعة الشاملة كاملة دون تغيير. |

لا تُثبّت الأدوات الخارجية إلا بعد الحصول على **موافقتك الصريحة على كل أداة**، وبالاعتماد على **المصدر والإصدار المثبّت بدقة** المحددين في `methodologies/<name>/requirements.json`.

## الأوامر

مُشغّل واجهة سطر الأوامر هو `maestro.cmd` على Windows و`./maestro` على macOS وLinux. ويعمل الأمر `python scripts/maestro.py` على جميع المنصات.

| الأمر | الغرض |
|---|---|
| `maestro --version` | طباعة إصدار البرنامج |
| `maestro init <project> [--methodology standard\|uem\|custom]` | إنشاء مجلد `<project>/.maestro/`. يمكن إعادة تشغيله بأمان لتحديث القوالب والقواعد. |
| `maestro tools <project> [--approve ID...]` | فحص أدوات المنهجية؛ وكتابة مهمة تثبيت للأدوات الموافق عليها |
| `maestro new <project> "<title>" [--feature ID]` | إنشاء وصف المهمة التالية (`task-NNN.md`) |
| `maestro send <project> [NNN] [--no-enter] [--allow-current-project]` | إرسال المهمة `NNN` (افتراضياً: أحدث مهمة) إلى Antigravity |
| `maestro wait <project> [NNN] [--timeout 45]` | الانتظار حتى وصول التقرير (دون استهلاك توكن؛ ينتهي بالرمز 3 عند وجود أسئلة أو نقاط مراجعة) |
| `maestro answer <project> <question-id> "<text>" \| --file FILE` | الإجابة عن سؤال المنفّذ (استخدم `--file` للإجابات متعددة الأسطر) |
| `maestro heldout <project> add\|list\|run <feature> [files]` | إدارة اختبارات القبول المحجوبة والمخزنة خارج المستودع |
| `maestro review <project> new <feature> [--task NNN]` | إنشاء ملف جولة المراجعة التالية (ينتهي بالرمز 4 عند استنفاد الجولات) |
| `maestro review <project> verdict <feature> accepted\|changes-requested` | تسجيل قرار المراجع في `feature_list.json` |
| `maestro testdiff <project> [--base REF]` | الكشف عن الاختبارات المحذوفة أو المضعفة أو المتجاهلة منذ فرع الأساس (ينتهي بالرمز 5 عند وجود تغييرات) |
| `maestro release <project>` | إزالة علامة المهمة النشطة بعد التخلي عن مهمة ما |
| `maestro status <project>` | عرض حالة المهام والأسئلة وحالة المهمة النشطة |

رموز الخروج:

| الرمز | المعنى |
|---|---|
| 0 | نجاح العملية، أو إرسال المهمة، أو جاهزية التقرير |
| 1 | خطأ، أو انتهاء مهلة الانتظار، أو فشل أحد الاختبارات المحجوبة |
| 2 | صياغة نص المهمة في Antigravity دون الضغط على مفتاح Enter (راجع الإشعار أو سبب المشكلة المطبوع) |
| 3 | استيقاظ الانتظار بسبب سؤال غير مجاب عنه من المنفّذ أو وجود نقطة مراجعة للخطة |
| 4 | استنفاد جولات المراجعة المتاحة (عبر أمر `review new`)؛ ويجب التصعيد إلى المستخدم |
| 5 | اكتشاف تغييرات في الاختبارات عبر `testdiff` تتطلب كتابة مبرر صريح |
